# AI Harness & Orchestration — 실무에 적용하는 AI 에이전트 실행과 협업

## 강의 개요

AI 에이전트가 업무를 수행하는 실행 환경과 작업 조율 방식을 다룬다. 하네스를 통해 에이전트가 어떤 도구와 맥락으로 작업하는지 살펴보고, 오케스트레이션을 통해 작업 순서와 역할을 어떻게 구성하는지 설명한다.

강의는 하네스 소개, 오케스트레이션 소개, 오케스트레이션 실습 순서로 구성한다. 실습에서는 pstack을 기본 후보로 두고, 역할별 개발 흐름을 보여주는 gstack도 검토한다. 스킬은 실습에 사용하는 작업 절차와 판단 기준을 담는 형식으로 간단히 소개한다.

## 강의 목표

수강생이 다음 내용을 이해하고 자신의 업무에 적용할 수 있도록 한다.

- 하네스를 구성하는 도구, 권한, 작업 맥락, 실행 결과 확인 방식을 설명한다.
- 업무의 의존 관계에 따라 작업 순서와 에이전트의 역할을 구분한다.
- 순차 실행과 병렬 실행이 적합한 상황을 판단한다.
- 실습에서 실행 환경, 작업 조율, 스킬이 각각 맡는 역할을 확인한다.

## 핵심 메시지

AI 에이전트에 업무를 맡기려면 작업에 필요한 실행 환경과, 작업을 진행하고 검증하는 절차를 함께 구성해야 한다.

하네스는 에이전트가 도구를 사용하고 실행 결과를 확인할 수 있게 한다. 오케스트레이션은 작업 단계와 역할, 실행 순서, 결과 취합을 조율한다. 실습에서는 이 환경 위에서 스킬의 지침에 따라 작업이 진행되는 과정을 살펴본다.

## 목차와 주요 내용

### 1. 하네스 소개

하나의 업무 요청이 실제 작업으로 이어지는 과정을 통해 하네스의 역할을 설명한다.

- 에이전트에게 제공하는 작업 맥락과 지침
- 파일 읽기, 검색, 명령 실행에 사용하는 도구
- 도구 사용 권한과 사람이 확인해야 하는 작업
- 도구의 실행 결과를 읽고 다음 행동을 결정하는 과정
- 작업의 완료 여부를 확인하는 방법

문서를 검토하거나 코드 문제를 조사하는 사례를 들어, 에이전트가 필요한 자료를 읽고 도구를 사용하며 결과를 확인하는 과정을 보여준다.

### 2. 오케스트레이션 소개

업무를 여러 단계로 나누고, 각 단계가 어떤 결과를 받아 무엇을 만들어야 하는지 설명한다.

- 조사, 작성, 검토 단계 사이의 의존 관계
- 순서대로 처리할 작업과 독립적으로 처리할 작업
- 한 에이전트가 이어서 수행할 범위와 다른 에이전트에게 맡길 범위
- 역할별로 전달할 맥락과 기대 결과물
- 여러 결과를 취합하고 의견 차이를 확인하는 기준
- 검증에 실패했을 때 돌아갈 단계와 작업을 종료할 조건

같은 업무를 순차 실행과 병렬 실행으로 구성한 예를 비교한다. 병렬 실행에서는 작업 중복, 맥락 전달, 같은 파일의 동시 수정도 함께 살펴본다.

### 3. 오케스트레이션 해보기

Codex에서 하나의 개발 업무를 수행하고, 앞에서 설명한 개념을 실제 실행 과정과 연결한다. 실습 도구는 pstack과 gstack 중 보여줄 작업 흐름과 Codex 실행 환경에 맞춰 선정한다.

1. 업무 목표, 입력 자료, 완료 조건을 전달한다.
2. 작업 단계와 역할, 각 단계에서 다음 단계로 전달할 결과를 확인한다.
3. 작업에 사용하는 스킬을 확인하고 핵심 지침을 읽는다.
4. 에이전트가 도구를 사용하고 작업을 진행하는 과정을 관찰한다.
5. 역할 분담이 있는 경우 각 에이전트의 입력과 결과를 확인한다.
6. 결과를 취합하고 검토 의견에 따라 보완한다.
7. 최종 결과물이 완료 조건을 충족하는지 검토한다.

스킬은 이 실습 안에서 사용 조건, 수행 절차, 판단 기준을 담은 지침으로 소개한다. 사용한 스킬의 지침 일부와 실제 실행을 연결해 설명한다.

실행 환경이 제공하는 기능과 스킬의 지침이 요구하는 행동을 구분해서 짚는다. 예를 들어 파일을 읽는 도구는 실행 환경이 제공하고, 어떤 파일을 어떤 목적으로 확인할지는 작업 지침에 담는다. 같은 에이전트가 역할을 바꾸어 순차 작업하는 경우와 여러 에이전트를 실제로 실행하는 경우도 구분한다.

실습 결과를 바탕으로 자신의 업무에 필요한 실행 환경과 작업 구성을 정리한다.

- 작업에 필요한 자료와 도구가 충분했는가
- 각 단계와 역할의 범위가 명확했는가
- 병렬로 나눈 작업이 서로 독립적이었는가
- 결과를 검증할 근거가 있었는가
- 사람이 판단해야 할 사항이 드러났는가

자료가 부족했다면 입력 맥락을, 같은 작업을 중복했다면 역할 구분을, 완료 여부를 판단하지 못했다면 검증 기준을 살펴본다.

## 실습 도구 후보

| 도구 | 실습에서 살펴볼 흐름 | 선정 시 확인할 사항 |
|---|---|---|
| pstack | 업무에 맞는 스킬과 플레이북 선택, 작업 분담, 검증과 결과 취합 | 선택한 플레이북에서 단계 전환과 역할 분담이 어떻게 드러나는지 확인 |
| gstack | 기획, 설계, 코드 검토, QA 등 역할별 작업과 결과 전달 | 선택한 스킬의 Codex 지원 범위와 추가 도구 의존성 확인 |

gstack은 역할별 스킬과 계획 검토 흐름을 제공한다. 역할 전환과 단계별 결과 전달을 중심으로 설명할 때 실습 후보로 검토한다. Codex 설치 경로도 안내하지만, 실제로 사용할 스킬의 동작은 강의 환경에서 확인한다.

## 실습 후보

아래 후보 중 수강 대상과 강의 환경에 맞는 사례를 선정한다.

| 후보 | 실습 내용 | 확인할 개념 |
|---|---|---|
| 코드 구조 조사와 설명 | 서로 다른 모듈을 조사하고, 모듈 간 호출 관계를 연결해 설명 | 검색과 파일 읽기, 조사 역할 분담, 결과 취합 |
| 코드 문제 조사와 수정 | 문제를 재현하고, 원인을 조사한 뒤 수정 결과를 검증 | 명령 실행, 단계 간 의존 관계, 실패 시 재작업, 완료 조건 |
| 업무 문서 작성과 검토 | 제공된 자료로 초안을 작성하고, 사실 근거와 누락 사항을 검토 | 자료 접근, 작성과 검토 역할 구분, 검토 결과 반영 |

역할 분담을 보여줄 때는 각 에이전트가 맡은 범위와 반환한 결과를 확인한다. 순차 실행을 보여줄 때는 앞 단계의 결과가 다음 단계의 입력으로 어떻게 사용되는지 확인한다.
