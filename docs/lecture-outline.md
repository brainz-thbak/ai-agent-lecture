# Advanced Skill Engineering — 실무에 적용하는 AI 스킬 설계

## 강의 개요

팀에서 중요하게 생각하는 업무 기준과 반복 작업을 AI 스킬로 구성하고, Codex에서 직접 만들고 평가한다. 코드 리뷰 표준화와 테스트 케이스 작성 자동화를 주요 실습 사례로 다룬다.

실습 주제는 각 팀이 표준화하거나 자동화하려는 업무에 맞춰 조정한다. 팀의 기준을 스킬에 담고 실제 산출물로 효과를 확인하는 과정을 중심으로 구성한다. pstack은 스킬 활용 사례로 간단히 소개한다.

## 강의 목표

수강생이 다음 내용을 자신의 업무에 적용할 수 있도록 한다.

- 팀에서 표준화하거나 자동화할 업무와 적용 범위를 정한다.
- 팀의 업무 기준을 스킬의 수행 절차와 판단 기준으로 작성한다.
- Codex에서 스킬을 호출하고 실제 업무 자료에 적용한다.
- 기존 업무 방식의 결과와 스킬 적용 결과를 비교하고 스킬을 개선한다.

## 핵심 메시지

팀이 중요하게 생각하는 기준을 반복해서 적용할 수 있도록 스킬로 만들고, 산출물이 그 기준을 충족하는지 평가한다.

코드 리뷰에서는 공통 검토 기준과 근거 있는 지적을, 테스트 케이스 작성에서는 요구사항과 연결되는 검증 가능한 시나리오를 목표로 삼는다. AI가 생성한 결과는 팀의 기준에 따라 사람이 검토한다.

## 목차와 주요 내용

### 1. 스킬 소개와 업무 선정

AI 스킬의 역할과 기본 구조를 소개하고, 팀의 업무에서 적용 대상을 고른다.

- 스킬의 사용 조건, 수행 절차, 판단 기준, 기대 결과물
- `SKILL.md`의 이름, 설명, 본문과 보조 자료의 역할
- 팀에서 반복해서 전달하는 지침과 자주 누락되는 검토 항목
- 표준화할 기준과 자동화할 작업의 범위
- 사람이 판단하거나 추가로 확인해야 하는 사항

코드 리뷰 표준화와 테스트 케이스 작성 자동화를 기본 사례로 제시한다. 팀별 우선순위에 따라 다른 업무를 선택하더라도 업무 선정, 기준 정리, 스킬 제작, 적용, 평가의 흐름은 유지한다.

### 2. 팀의 기준을 담은 스킬 만들기

선택한 업무의 자료와 기준을 바탕으로 스킬을 작성하고 Codex에서 호출한다.

#### 코드 리뷰 표준화 스킬

팀의 리뷰 기준에 따라 변경 코드를 검토하고, 지적 사항과 근거를 일정한 형식으로 정리하는 스킬을 만든다.

- 입력 자료: 코드 변경분, 관련 코드, 팀의 리뷰 기준
- 검토 범위: 오류 처리, 경계 조건, 권한 확인, 팀 규칙 중 업무에 해당하는 항목
- 판단 기준: 문제의 근거와 영향, 필수 수정과 개선 제안의 구분
- 출력 형식: 문제 위치, 지적 내용, 근거, 수정 제안
- 예외 처리: 근거가 부족하거나 추가 맥락이 필요한 사항 표시

팀의 기준을 실제 변경 코드에 적용해 보고, 지적의 타당성과 누락 여부를 검토한다.

#### 테스트 케이스 작성 자동화 스킬

요구사항과 수용 기준에서 테스트 시나리오를 도출하고, 팀의 형식으로 테스트 케이스 초안을 작성하는 스킬을 만든다.

- 입력 자료: 요구사항, 수용 기준, 관련 명세, 팀의 테스트 케이스 양식
- 도출 절차: 요구사항별 정상 흐름, 경계 조건, 예외 상황 확인
- 판단 기준: 요구사항과의 연결, 중복 여부, 기대 결과의 검증 가능성
- 출력 형식: 관련 요구사항, 사전 조건, 입력값, 수행 절차, 기대 결과
- 예외 처리: 명세가 모호하거나 기대 동작이 정의되지 않은 사항 표시

생성된 테스트 케이스에서 누락, 중복, 근거 없이 가정한 동작을 확인한다. 자동화 대상은 테스트 케이스 초안 작성으로 두고, 실행 가능한 테스트 코드 생성은 팀의 필요에 따라 범위를 정한다.

#### 루프 엔지니어링 소개

테스트 케이스를 생성하고 검토 결과에 따라 보완하는 과정을 통해 루프 엔지니어링을 소개한다. 이 강의에서는 작업 결과에 대한 피드백, 재작업 절차, 종료 조건을 설계하는 것으로 설명한다.

1. 요구사항과 수용 기준에서 테스트 케이스를 생성한다.
2. 요구사항별 누락, 중복, 경계·예외 상황, 기대 결과의 검증 가능성을 확인한다.
3. 검토에서 발견한 문제와 근거를 다음 작업의 입력으로 전달한다.
4. 테스트 케이스를 보완하고 같은 기준으로 재검토한다.
5. 종료 기준을 충족하면 결과를 확정하고, 해결하지 못한 항목은 사람에게 전달한다.

- 피드백 기준: 요구사항과 케이스의 연결, 필수 시나리오 포함 여부, 기대 결과의 명확성
- 종료 조건: 합의한 필수 검토 항목을 충족하고, 남은 불확실성을 표시한 상태
- 중단 조건: 반복 횟수 한도 도달, 개선이 없는 반복, 명세 부족으로 추가 판단이 필요한 경우

명세가 모호한 항목은 확인 질문으로 남긴다. 반복 중에도 요구사항과 검토 기준을 유지하고, AI의 자체 검토만으로 정확성을 확정하지 않는다. 테스트 코드 생성·실행까지 다루는 경우에는 실행, 실패 원인 분석, 수정, 재실행으로 연결한다.

### 3. 만든 스킬 적용하고 평가하기

기존 업무와 스킬 적용 결과를 같은 기준으로 비교한다.

- 기존 업무의 입력 자료, 수행 방식, 결과물 정리
- 같은 입력에 스킬을 적용해 결과물 생성
- 팀의 기준에 따른 정확성, 누락, 불필요한 내용 평가
- 수정이 필요한 결과와 사람이 개입한 지점 확인
- 평가 결과에 따라 스킬을 수정하고 다른 입력에도 적용

| 실습 주제 | 평가할 항목 |
|---|---|
| 코드 리뷰 표준화 | 팀 기준 적용 여부, 준비한 결함의 탐지 여부, 잘못된 지적, 위치와 근거의 정확성 |
| 테스트 케이스 작성 자동화 | 요구사항별 누락, 경계·예외 상황 반영, 중복, 기대 결과의 검증 가능성, 명세에 없는 동작의 가정 |

기존 방식의 결과물과 스킬 적용 결과물을 함께 확인한다. 기존 결과물도 동일한 기준으로 검토한다. 작업 부담은 사람이 추가로 확인하고 수정한 내용을 바탕으로 살펴본다.

스킬 자체의 효과를 비교할 때는 같은 모델, 도구, 입력, 사용자 요청을 사용하고 독립된 환경에서 스킬 사용 여부를 바꾸어 실행한다. 평가 도구와 벤치마크 자동화 범위는 Codex 환경에서 동작을 확인한 뒤 정한다. 한 번의 결과와 반복 적용의 결과를 구분해 해석한다.

### 4. pstack 소개

pstack을 통해 스킬과 작업 절차를 구성한 사례를 간단히 소개한다.

- 업무 상황에 따라 스킬과 작업 절차를 선택하는 방식
- 다른 스킬과 참조 자료를 연결하는 방식
- 결과 검증을 작업 절차에 포함하는 방식

직접 만든 스킬에 참고할 수 있는 구성 요소를 짚는다.

## 실습 주제 선정 기준

코드 리뷰 표준화와 테스트 케이스 작성 자동화를 기본 후보로 두고, 각 팀이 중요하게 생각하는 표준화·자동화 과제에 맞춰 주제를 선정한다.

- 팀이 적용하려는 업무 기준을 설명할 수 있는가
- 실습에 사용할 입력 자료를 준비할 수 있는가
- 반복 적용할 필요가 있는 업무인가
- 결과물의 적절성을 확인할 기준이 있는가
- 강의에서 다룰 수 있는 범위로 작업을 좁힐 수 있는가

팀의 리뷰 체크리스트, 테스트 케이스 양식, 대표 업무 사례를 실습의 기준 자료로 사용한다.
